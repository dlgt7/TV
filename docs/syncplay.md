# Syncplay 一起看

两端各自打开同一影片，在 **播放器 → 选项 → 一起看** 中填写同一个 Syncplay 服务端、端口和房间，手动加入。服务器选择提供 `syncplay.pl:8995` 至 `syncplay.pl:8999` 和“自定义服务器”。首次使用不自动选择公共服务器；自定义端口默认为 `8999`。设置页也提供配置入口。

房间成员必须使用同一服务器、同一端口和同一房间名；这些公共端口不会自动互相切换。选择服务器只修改当前表单，点击“加入”才保存并连接。自定义地址在切换列表时保留，取消不保存；更换服务器端点会清空本次输入的服务器密码。

服务端填写主机名或 IP，不填写 URL。默认要求 TLS；服务端不支持 STARTTLS、证书不可信或主机名不匹配时连接失败，不自动降级。确实使用明文自建服务时，可手动关闭“要求 TLS 加密”。服务端密码只用于当前连接，不保存；服务器、端口、用户名、房间和 TLS 选项保存在本机，保存设置不会自动加入。

## 同步行为

- 通过 Media3 `Player` 接口支持 Exo 和 MPV，双向同步播放、暂停和拖动进度。
- 首次加入按房间位置对齐；空房间由本机当前进度初始化。
- 明显偏差（至少 2.5 秒）直接校正；较小偏差使用 `0.97x` / `1.03x` 缓慢修正，恢复对齐后回到 `1x`。
- 加入时使用正常倍速，离开时恢复加入前的倍速。手动选择其他倍速会退出房间并保留用户选择。
- 本机未加载完成、不可拖动或为直播时不应用远程控制；缓冲状态不会被误报为用户暂停。
- 先取得房间成员与媒体信息，再比较片名/集名和时长。片名忽略大小写、常见扩展名及部分分隔符；时长允许 2.5 秒差异。差异较大时显示提示并暂停同步，用户可手动确认是同一影片。任一方更换媒体或成员变化后重新核对。
- 远程控制触发的播放器回调及 Syncplay `ignoringOnTheFly` 确认均做回声抑制；快速连续操作保留最新位置。
- 离开房间、关闭播放页、播放器被释放或网络断开后恢复本地播放；不会自动重连。连接和 TLS 关闭均不占用 UI 线程。

只向服务器公布显示片名/集名、时长和未知文件大小（`0`），不传输播放地址、源配置、媒体文件或播放凭据。两端需要自行取得并打开影片。服务器和同房间用户可看到片名。

当前不实现聊天、共享播放列表、受控房间、就绪投票或自动打开媒体。不同片源即使同名也可能有片头、剪辑或广告差异；手动确认后需自行确认内容和时间轴一致。实际同步精度取决于网络、缓冲和播放器的 seek 精度。

## 实现与验证

协议依据官方 [Syncplay 1.7.7 源码](https://github.com/Syncplay/syncplay/tree/2af7ace347f437d44cd809a65c049e82bb4027fb)：`syncplay/protocols.py`、`syncplay/server.py`、`syncplay/constants.py`。使用 TCP 上的 UTF-8 JSON / CRLF 帧，支持 Hello、官方 MD5 服务端密码认证、Set/List、State、ping 和 STARTTLS；公布兼容版本 `1.2.255` 和实际协议版本 `1.7.7`。

`SyncplayProtocolTest` 与 `SyncplaySynchronizerTest` 覆盖协议确认、连续操作、房间过滤、分段 UTF-8 与帧上限、媒体校验及偏差校正。2026-10-06 的轻量 JUnit 检查共 12 项通过。

同日使用官方 1.7.7 服务端，在本机回环地址启动临时明文和 STARTTLS 实例，两名 Java 客户端完成 18 项互通检查：认证、媒体公布、双向播放/暂停/seek、连续操作、超过服务端超时周期的心跳、退出、错误密码、不允许 TLS 降级、自签证书拒绝、主机名不匹配拒绝，以及测试专用信任库下的成功 STARTTLS。测试不连接公共服务器；测试证书与信任库不进入应用。

全部新 Java 类另经 Android SDK 37、Media3 1.11.0、Material 1.14.0 和 AppCompat 1.7.1 的实际 API 编译检查。随后在 [Android 构建运行 37531559188](https://github.com/wobuhui666/TV/actions/runs/37531559188) 完成 TV `arm64-v8a` 的 `preview` 与 `sourceprobe` debug 应用及测试 APK 构建，对应应用提交 `decc4857ab37296595414ba2402729b6028a4fc1`。

2026-10-06，在三星 SM-F900F（Android 13）专用 `sourceprobe` 包执行真实 Exo 集成测试通过：一项 instrumentation 用例包含以下 9 个检查点。

1. 真实 Exo 加载完成并选中音轨。
2. 生产代码中的 Syncplay 会话与测试对端加入同一媒体房间。
3. 对端播放命令推动实际 Exo 播放时钟。
4. 对端暂停命令停止实际 Exo 播放时钟。
5. 对端 seek 到达真实 Exo。
6. 远程 seek 后，在回声抑制窗口内进行的邻近用户 seek 仍发送给对端。
7. 离开房间恢复加入前倍速。
8. 离开后忽略对端控制，保留本地播放和 seek。
9. 主线程 StrictMode 网络违规为 0。

该用例使用 30 秒固定媒体、官方服务端和回环连接；本次设备连接为明文，TLS 结论来自前述独立协议互通测试。实测播放时钟前进 502 毫秒、暂停时钟偏差 0 毫秒；这些是本次断言的观察值，不代表跨设备同步误差。测试结束已恢复偏好并关闭播放器和会话。

目前仍未完成两台真实设备同时播放的端到端同步验收，也未由上述 Exo 用例验证 MPV 同步精度。跨设备网络延迟、不同源时间轴和长时间漂移仍需独立实测，不能由协议互通或单台三星测试推定。
