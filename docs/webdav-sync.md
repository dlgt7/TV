# WebDAV 多设备同步

在 **我的 → 设置 → 多设备同步 · WebDAV** 中填写 WebDAV HTTPS 地址、账号和应用密码。地址以 `/` 结尾时，会在该目录使用 `tv-sync-v1.json`；也可以填写专用 JSON 文件地址。请先在 WebDAV 服务中创建父目录。不要把 `wex.json` 等源配置文件作为同步文件；应用遇到非同步格式会停止，不会覆盖它。

每台设备填写同一地址和账号，选择需要同步的数据，再按“立即同步”。默认同步收藏与观看进度，自动同步默认关闭。启用自动同步后，应用进入前台、前台每 15 分钟，以及离开前台保存进度后会尝试同步；失败不会连续请求服务器。没有常驻后台同步服务。

## 数据范围

- 收藏和观看进度按订阅地址、订阅类型、来源记录 ID 匹配，不按片名合并，也不复制另一台设备的数据库编号。默认要求两端已经添加同一订阅。
- 可选“订阅地址”只同步可移植的 HTTP(S) 地址和名称。带账号密码或认证查询参数的地址、源配置缓存不会上传；这些订阅需要在各设备自行添加。不会切换当前使用的源。
- 可选偏好仅包括弹幕显示、字号和透明度。解码器、音频直通、代理、ECH、播放器设备选项和 WebDAV 凭据均不参与同步。
- 观看记录保留本机的倍速、画面缩放等播放设置。导入进度后由本机源重新解析播放地址，不同步临时媒体 URL。

收藏与历史的删除会同步。首次使用的空设备不会被解释为“删除全部数据”。订阅只新增或更新，其他设备删除订阅不会移除本机正在使用的配置。当前数据库不支持在不同订阅中保存相同主键的两条记录；遇到这种情况会跳过并显示数量，保留本机记录。

## 冲突与连接

每条记录独立合并，保留删除标记。正在播放时新写入的进度、同步期间的本地编辑会保留，下一轮再上传。同步不清空数据库，不重建当前播放器。

服务器需要支持版本 ETag 和条件写入：已有文件使用原始 ETag 的 `If-Match`，兼容坚果云的未加引号版本标识，拒绝弱 ETag 和通配符。首次创建先上传同目录的唯一临时文件，再通过 `MOVE`、`Overwrite: F` 发布；另一台设备抢先创建时不会覆盖它。遇到创建冲突或版本变化时，重新读取合并，最多三次；不会退回无条件覆盖。网络中断后本地待同步变更和删除标记仍保留。

连接使用 HTTPS 和标准证书验证。账号只发给填写的服务器，不跟随重定向转交认证信息。服务端需允许 GET、PUT、MOVE 和 DELETE；401/403 表示账号或权限需要检查，缺少 ETag 或不支持禁止覆盖移动的服务不能用于此同步方式。

同步文件包含所选收藏和观看记录，请使用自己的 WebDAV 账户。同步凭据独立保存在本机，不写入云端同步文档或普通偏好备份。

## 验证

合并、离线删除、并发编辑、条件 HTTP、取消与重定向隔离有 JVM 测试。`WebDavSyncIntegrationTest` 使用真实 Room 双实例、独立 AtomicFile 日志和回环 HTTP，验证不同设备编号映射、播放中写入保护、删除传播及订阅冲突；只允许在专用 `sourceprobe` 测试包运行。

2026-10-06，在三星 SM-F900F（Android 13）的专用 `sourceprobe` 包执行该集成测试，结果为 **7 项通过**：

1. 按订阅 URL 和类型映射不同设备的本地数据库 ID。
2. 离线删除在日志重新打开后继续保留，不让已删除记录复活。
3. HTTP GET 期间写入的播放进度在下一轮同步中保留。
4. 同步指纹保护本地专用字段，后续导入也保留这些字段。
5. Room 提交后发生的播放器写入不会被误标为已经同步。
6. 不同订阅的主键冲突不会覆盖或删除其他订阅记录。
7. 可选订阅导入使用新的本地 ID，排除源缓存和凭据。

这次使用单台三星上的两个独立 Room 实例和回环 HTTP，验证真实 Android 数据库与同步流程；没有访问公共 WebDAV，也不等同于两台真实设备经坚果云等服务完成端到端同步验收。

同日另用坚果云同目录的独立临时文件验证真实服务器行为：原始裸 ETag 的当前版本更新成功，错误或过期版本返回 412；直接 PUT 的 `If-None-Match: *` 未阻止重复创建，因此应用改用上述 MOVE 流程。实测 `Overwrite: F` 在目标存在时返回 409，源文件和目标内容均保持不变；目标不存在时返回 201 且原临时文件消失。测试文件已清理，没有对订阅配置文件执行这些竞争测试。

修复后的生产 `WebDavTransport` 另经两个 Java 客户端连接坚果云验证通过：两个客户端先看到文件不存在，第一端创建成功，第二端的过期创建冲突；重新读取后使用裸 ETag 合并两端记录成功，过期版本写入不能丢掉另一端记录。最后按当前 ETag 删除专用测试文档并确认 404。该验证使用固定测试记录，不上传真实收藏和观看进度；WebDAV 的本地 JVM 回归共 39 项通过。
